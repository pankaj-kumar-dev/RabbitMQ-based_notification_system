What you're watching
1

Normal flow: Send a notification. Row appears as PENDING. Within 2s the outbox poller picks it up (FOR UPDATE SKIP LOCKED) and publishes to RabbitMQ. Consumer ACKs → PROCESSED.

2

Retry chain: Set FAIL_MODE=true and restart consumer. Send a notification. Consumer throws → NACK (requeue=false) → DLX fires. Message cascades: retry_1s (1s TTL) → retry_5s (5s TTL) → retry_30s (30s TTL) → DLQ. Watch the queue depth bars fill.

3

Idempotency: In the retry scenario, Redis already claimed the eventId on the first attempt. If FAIL_MODE is re-disabled, the retried message hits Redis SET NX — key exists → duplicate → ACK and drop. No double-processing.
